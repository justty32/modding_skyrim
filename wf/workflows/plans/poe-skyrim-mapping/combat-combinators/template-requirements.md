# 每個子型的填圖範本要求

[母題](README.md)｜[刻印第一樣板](inscription-sample/README.md)

> 11-04家中場使用者新要求「所有職業都做一做」，本輪依既有八職×三子類展開24設計樣板，見[全職業入口](all-classes/README.md)。下方「先交一型再擴」保留原流程來源，本輪設計擴展以此新指示為準；其他品質、原圖、數值過目及source/runtime界線不變。

2026-11-04 使用者先說「單一職業子型，我預期會有1~3個高階規則，4個以上的進階規則」，再補「同一職業下的不同子型，可以共享一些規則，但是每個子型至少要有兩個獨特的高階規則、三個獨特的進階規則」。兩條合併後，每子型高階總數為2–3，其中至少2獨特；進階至少4，其中至少3獨特。這是後續範本共同要求，不只是刻印本輪臨時規模。

獨特是與同職業兄弟子型相比的玩法辨識度：觸發、狀態歸屬、消費或行為關係要有實質差異，不能換名或換倍率充數。底層組合子可以共用；不因此加入職業鎖、不禁止玩家混搭。每條規則記錄owner/subtype、shared_with、unique_against與機制理由，計數須實核，兄弟型仍只是對照邊界，不能為了證unique順手全型填圖。

另依同日使用者裁示，職業還要有不屬任何子型的class-common通用池：高階1–3、進階3–5。這一池不拿來充子型最低數；跨子型共享規則另記subtype-shared scope，也不和class-common或unique混算。

普通層是純數值；進階是規則＋數值（條件增傷、資源轉換、帶門檻的強度等）；高階以徹底改變玩法的純規則為主，少數可為無條件的極端純數值交換。這是使用者在同日「通常高階有誇張buff/debuff」後再精確校正的現行分類；不能把「雙施時加百分比」或「帶狀態的大倍率」只因數字大就算高階。若原型混有新行為與條件強度，高階保留玩法規則，進階或獨立待審強度參數承擔數值，不重複計點／預算。

High仍須寫選前打法、選後打法、得到、付出、無法用普通數值替代的理由及可抵銷／互動風險；大收益／大代價是可用設計手段，不是每條一律倍率交換的強制規格。schema只能核聲明欄位，實質遊戲性由設計師與使用者過目。舊凍結成品與已議keystone不因此重寫。原圖節點ID、位置、類型與邊不改；新設計tier不等於PoE node type。高階掛notable只是候選placement，不能默認取代48個已議keystone。基本數值及節點1／3／5份、無runtime caps裁示不改，新規則成本與能力預算拆分需另過目。

第一輪先交一個子型的真區域可審稿：保留入口、外接邊、mastery孔洞與受保護keystone；列普通／進階／高階效果、選點路徑、可操作情境與待證能力，驗ID/連通/原拓撲/總數與unique數。使用者看過樣板後，才以其回饋擴充其他子型，未過目不全樹套用。

## H0先解鎖 原生法術被動附印

使用者同日新裁示：擊中後附印本身是高階規則，點亮後才有後續印進階可點。本輪以61308作可由普通路抵達的核心H0，不再每一個進階暗送共同載具。印進階至少需要H0；付費印強化／回流／改寫還需A1真付費印，免費H0狀態不能憑空算P/B。圖連通與規則前置皆成立才可購買，compiled未ready仍拒買；Debug不繞前置。

退款沿既有整actor免費Reset，保高水位、清allocation與debug前快照及暫態，沒有新增單點退款。High轉構未完成不許先花點；刻印仍只H0＋一transform兩High，未落變體不充第三，更不挪用保護keystone。
