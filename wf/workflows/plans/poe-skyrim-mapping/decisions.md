# 已定裁示（現行）

[README](README.md)｜[design](design.md)｜[mechanics](mechanics.md)｜[keystones](keystones.md)

使用者已定的事全部集中在這裡，寫成現在式。2026-11-03 前段的原話全文在 [user-words-2026-11-03.md](user-words-2026-11-03.md)；後段原話引自各線報告，出處在各條後面。

## 1. 點數與節點權重

- 每級 1 點，`earned = 1 × 最高觀察等級`，L1 就有 1 點。原話：「5.1級一點」。
- 節點權重：小點 1 份、大點（notable）3 份、keystone 5 份；一般鑲嵌座當通路，算 1 份。原話見 user-words 原話一。
- 珠寶鑲嵌忽略。
- 舊存檔免費重置。使用者回覆「45都按照建議」時定案。

## 2. 誰用星盤

- 玩家也用這個星盤，直接疊加在原版 perk 上，不取代 perk，也不對玩家打折。玩家在 L50 可能達到約原版 ×2，使用者接受。原話：選 (c)「直接疊加」（user-words 原話二）。
- 隨從以星盤為唯一的 perk 來源。

## 3. 數值

- 每份數值寫在 [atoms.json](data/atoms.json) 的 `per_share` 欄，一律整數。原話：「有小數點的，都四捨五入」（.5 進位；[poe-calib](../../../../agentctl/handoffs/home-2026-11-03/poe-calib/REPORT.md)）。
- **50 份校準**：L50 共 50 點。每份數值以「50 份全灌同一效果 ≈ 原版 L50 或使用者給的基準」反推。基準只用來反推每份數值。原話：「40...改50吧，這樣更舒服」；實際 50 點拿到 80–90 份、多數效果湊不滿 50 份，使用者接受：「50份只是理想，我覺得現在這樣就OK」。
- 數值以原版護甲等級和傷害為參考；武器傷害以該等級的弓、單手劍、雙手劍為基礎。

各類每份數值（全表在 atoms.json）：

- 增傷採寬鬆版：單類 1H／2H／弓 +3%、毀滅 +2%、近戰兩類 +2%、全物理 +2%、全傷害 +1%。規則是「範圍越廣，每份 ≤ 窄的那類」。
- 純法 L50 毀滅約 +116%，高過原版 Augmented +50% 與武器類，使用者接受（原話「a」，poe-calib 第 5 節）。
- 回復：HP +5%／份，SP、MP +10%／份。
- 元素抗、毒抗、魔抗 +2／份。

映射方式：

- 三屬性：Str→HP＋SP、Dex→AR＋SP、Int→MP＋法傷，份額見 [design 第 2 節](design.md#2-拆分規則)。原話：「三術性我覺得可以」。
- 命中、閃避一律映射到護甲。對不上的節點換成小加成，可以拆到多個數值。原話：「換成小加成，並且可以分散到多個數值上，比如閃避可以變成護甲加成+一點點攻速之類」。

## 4. 上限：不設

星盤不設任何 runtime 上限，也不夾值。原話（poe-calib 第 2 節）：

> 我的意思是，我們以50級訂下了這些效果單位，整個星盤就這樣子就好

> 明定的固定上限那個，也只是拿來做效果單位基準的。我們不設上限。

- 依等級上限、L50 後脫鉤到 +100% 都不採用。
- 引擎本身的限制（抗性 85% 封頂、護甲減傷 80% 封頂）與疊高的後果（例如 0 耗），使用者接受。原話：「不用，那些都沒差」。

## 5. 速度

- 全圖節點全買時，移速靜態加總 ≤ 30%、攻速 ≤ 50%。原話：「移動速度以30%為上限，攻擊速度以50%為上限」。
- 單點速度 ≤ +5%。原話：「單點最多5%...定下吧」。
- 這三個數字是分配份額時的**設計檢查**，不在 runtime 夾值。
- 原本被改成傷害或耗能的速度效果，可以分一部分回速度。原話：「你看，我們設成50%之後，數值就有餘裕了。一些反映到skyrim的數值後，可以稍微分配進來」。攻速 rule 的攻速份額定為 0.4；三條速度 rule 的份額在 [family-rules.json](data/family-rules.json)。
- 之後新增任何帶攻速的 rule，都要重跑全圖攻速加總的設計檢查（現在 48.9%，只剩 1.1）。
- 施速 rule 不動。施法速度等使用者提供參考 mod 再定。
